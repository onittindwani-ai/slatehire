# Security and data

- **Sign in** is required on every route except sign in and the signed application webhook. Sessions are httpOnly cookies set by the web app; the API stays private. Changes through the web app need a header a cross site page cannot send.
- **Roles:** owner (everything) and approver (decide approvals, send scorecards, plan and score). Only the owner can delete a candidate, import voluntary labels, run the fairness report, turn blind mode off for a role, run the demo reset and use the kill switch.
- **Identity hiding** runs before anything reads a resume. While blind mode is on the server refuses to return names, emails or schools, whatever the page asks for.
- **Untrusted text:** a resume is data. Lines that talk to the scorer are flagged, never scored and never quoted. Nothing in a resume can trigger an action.
- **Audit log:** hash chained and append only. The app refuses to edit or delete a row, and the chain check finds an edit made outside the app. The log holds the neutral candidate code, never a name or an email.
- **Fairness labels** sit in their own table and are read only by one module. A test checks this. Scores do not change when labels change. A group below `FAIRNESS_MIN_GROUP` is saved and shown as "fewer than N" with no counts, so a small group cannot be picked out by subtraction, and an older report that flagged a group stays visible after a clean one.
- **Protected traits:** a rubric that looks for a word that stands in for one (age, school, language, gender coded words; add your own in `PROXY_TERMS`) is refused when it is locked, and the source of an application is shown as a channel only while the identity is hidden.
- **Addresses people type** (a resume web address) go through a guard that refuses private networks, odd schemes and unsafe redirects. The name is looked up once and the connection goes to the address that passed, each redirect is checked again, and a fetch has a 30 second limit.
- **Sign in:** the address is compared without spaces or capitals; tries are limited per visitor, per address and per account; an unknown address costs the same work as a wrong password. The web app passes on only the last address in `X-Forwarded-For`, because earlier ones are typed by the caller. The public demo logins and demo buttons switch off by themselves once `OWNER_PASSWORD_HASH` is set, and the API and worker refuse to start outside the demo on an example `SESSION_SECRET`.
- **Two people on every offer:** the person who asked for approval and the person who last wrote the terms both cannot approve; the approval screen shows the whole letter. A line break in a name or title cannot add a term to an offer file.
- **Limits:** a request is refused as it arrives when it is over `MAX_BODY_BYTES` (a resume file: `UPLOAD_MAX_BYTES`), whatever length it claims. An applicant's name and email travel in headers, so web server and proxy logs never hold them.
- **Secrets** are only in the environment, never in the repository. `python3 tools/scan_secrets.py` scans the tree.
- **Mail:** applications are read with `BODY.PEEK[]` and marked read only after the application is stored. One message that cannot be stored is skipped alone, with a reason and no candidate text in the log. The mailbox connection checks the server certificate and name; plain text is allowed only for a server on this same computer.
- **Nobody drops out unseen:** every application that arrives by email, an ATS or a form and is not added (a duplicate, a refused file) has a line with the reason on the Candidates page. A resume nobody can read still brings the applicant in, marked "Resume missing" and not scored.
- **Personal data:** applicant text is stored. Delete on request or by retention. Deleting also takes the name out of the offer text and of any offer file already written, clears the notes and the intake log lines. The sweep deletes declined and withdrawn people after `RETENTION_DAYS`, applicants nobody decided on after `OPEN_RETENTION_DAYS`, and old intake log lines. Backups keep it until they expire.
- **Someone who leaves:** declining or withdrawing a person closes their waiting offer (it shows as withdrawn, the approval is rejected, and nothing can be approved or written for it afterwards).
See `SECURITY.md` for reporting a problem.
